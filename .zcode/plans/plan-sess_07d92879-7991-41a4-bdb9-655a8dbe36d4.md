實作 Phase 6：Riverpod MVVM、UI 接駁及移除舊架構。這是唯一集中修改多個 production files 的階段。完成後 Expression Tree 是唯一算式資料來源，舊字串架構與 FractionDraft 全數移除。

## 重寫的 production 檔案

1. **`lib/.../model/expression/expression_document.dart`**
   - 移除舊字串版 `ExpressionDocument`（evaluationExpression、texExpression、offsets、openParentheses）。
   - 改為別名指向 Tree 版：`typedef ExpressionDocument = TreeExpressionDocument`。
   - 這樣 `CalculatorState` 與既有引用不需大改 import 路徑，且 Phase 6 後 `TreeExpressionDocument` 正式成為 `ExpressionDocument`。

2. **`lib/.../model/calculator_state.dart`**（重寫）
   - 欄位：`document`（TreeExpressionDocument）、`result`、`angleMode`、`errorMessage`、`hasEvaluated`、`answer`（上一個答案，供 Ans 常數）。
   - 刪除：`fractionDraft`、`isEditingFraction`、`_notSpecified` sentinel。
   - `copyWith` 對應簡化。

3. **`lib/.../viewmodel/calculator_providers.dart`**（重寫）
   - 註冊 Tree services：`TreeExpressionEditor`、`ExpressionNavigator`、`TreeExpressionTexSerializer`、`ExpressionValidator`、`ExpressionCompiler`、`TreeExpressionEvaluator`、`TreeCalculatorEngine`。
   - `calculatorViewModelProvider` 保持 NotifierProvider。

4. **`lib/.../viewmodel/calculator_view_model.dart`**（重寫）
   - 持有 `_editor`（TreeExpressionEditor）、`_navigator`（ExpressionNavigator）、`_engine`（TreeCalculatorEngine）、`_serializer`（選擇性，Screen 直接用 provider）。
   - 方法（UI intent 命名，對應計劃）：`inputDigit`、`inputDecimalPoint`、`inputAdd/Subtract/Multiply/Divide`、`inputSin/Cos/Tan/Log10/Ln`、`inputPi`、`inputEulerNumber`、`inputFraction`、`inputSquareRoot`、`inputNthRoot`、`inputPower`、`inputSquare`、`inputOpenGroup`、`inputCloseGroup`、`moveLeft/Right/Up/Down`、`backspace`、`clear`、`calculate`、`toggleAngleMode`。
   - 每個輸入方法：呼叫 editor/navigator → 寫入新 document → 清 result/error、`hasEvaluated=false`。
   - `calculate()`：呼叫 engine.evaluate(document.root, angleMode, answer)，成功存 result + answer + hasEvaluated=true，失敗放 errorMessage。
   - 任何輸入後清除 error（已確認）。
   - `(` 與 `)` 鍵都呼叫 insertGroup（已確認保留兩鍵；`)` 視為完成/離開群組的語意，但無 close 操作，故也呼叫 insertGroup）。
   - 移除所有 FractionDraft、moveFractionUp/Down、_commitFraction 邏輯。

5. **`lib/.../view/calculator_screen.dart`**（重寫）
   - 監聽 state，透過 `TreeExpressionTexSerializerProvider` 產生 `TexSerializationResult`。
   - `displayTex` = result.withHiddenCursor，`displayTexWithCursor` = result.withVisibleCursor，依 `hasEvaluated` 決定 cursorVisible。
   - fallbackText 改為空白或安全文字（不再讀 evaluationExpression）。
   - 連接 keypad callbacks 至新的 ViewModel 方法。

6. **`lib/.../view/widgets/natural_math_display.dart`**（微調）
   - 保留閃爍動畫邏輯，`fallbackText` 改為可空，預設顯示安全佔位（`|`），不再依賴 evaluationExpression。

7. **`lib/.../view/widgets/calculator_keypad.dart`**（微調）
   - 保留現有 layout 與所有 callback。
   - 新增 `onNthRoot` callback（若 keypad 要顯示 n 次根；MVP 可先不加，保持現有 5x6 版面）。**決定**：MVP 不新增 nth root 鍵，保持現有版面，避免視覺變動；nthRoot 仍可由 ViewModel 提供（未來擴充）。

## 驗收（計劃 Phase 6 + Definition of Done）
- Expression Tree 是唯一算式資料來源；production state 不再存 expression/TeX string。
- 無 evaluation/TeX cursor offset 同步邏輯；FractionDraft 已移除。
- 所有輸入透過 Tree Editor；所有方向移動透過 Tree Navigator；TeX 完全由 Tree Serializer 產生；計算完全由 Tree Engine。
- 錯誤只在按 `=` 後出現於 ResultDisplay，繼續輸入後清除。
- 函數 argument 可進出、分子分母可導航、根式指數可進出、游標閃爍不位移。
- `dart format` / `flutter analyze`（No issues）/ `flutter test`（全通過）。
